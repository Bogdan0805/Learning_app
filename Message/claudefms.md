## 1. Пользователь и правила работы

- Владелец репозитория **не программист**. Решения принимать самому, лишних вопросов не задавать (максимум один вопрос, и только после изучения кода).
- Отвечать **простым русским языком, коротко, без воды**. Команды для терминала пользователя — отдельными блоками кода, по одной команде в блоке.
- Опасное для проекта (снос данных, переписывание с нуля) — **сначала прямо предупредить**.
- Процесс: пользователь даёт репозиторий и токен GitHub в чате → клонировать → читать код → делать задачу → **проверять** (тесты + сборка) → коммит и пуш в `main`.
- Токен приходит в чате и **протухает быстро** (за этот проект уже 4 раза: каждый токен жил от нескольких часов до суток; признак: `Bad credentials` / `Authentication failed`). Коммит можно сделать локально и запушить, когда придёт новый токен (так уже делалось). Пользователю **не напоминать про отзыв токена**, но при реальной ошибке авторизации сказать, что нужен новый.
- Репозиторий: `https://github.com/Bogdan0805/Learning_app` (ветка `main`).
- **Релизы:** по просьбе владельца новые версии выкладываются как релиз **`003`** (файл `Bit-learning-app-003.apk`); релизы `002` и `latest` заморожены (старые сборки, не перезаписывать). Если владелец попросит новую нумерацию — менять `tag_name`/имена файлов в workflow и записать это здесь.
- Push по токену работает только в форме: `git remote set-url origin https://x-access-token:<TOKEN>@github.com/Bogdan0805/Learning_app.git` (формат `https://<TOKEN>@github.com/...` падает с «could not read Password»). При выводе логов маскируй токен: `| sed 's/ghp_[A-Za-z0-9]*/***/g'`.

## 2. Что за приложение

«Бит» — обучающее приложение по мотивам Duolingo (талисман — робот Бит), для не-программиста-владельца и его учёбы. Исходное ТЗ (сжато):

- Первичная настройка: выбор предметов и важности каждого (1–10) → «колесо фортуны» с вероятностями по важности → время и число уроков в день → первый урок (~10 минут).
- Урок: краткое введение по теме → ряд тестов (у каждого вопроса 3 жизни; после 3 ошибок показывается решение, обучение идёт дальше). Периодически — уроки-повторения по всему изученному.
- Напоминания: в заданное время уведомление; если за 5 минут пользователь не приступил — баннер на весь экран поверх всего; закрыть можно, вернётся через минуту; 3 стадии «грозности» (дальше стадия не растёт, баннер возвращается каждую минуту) — пока не пройден дневной урок.
- Перед уроком выбор: «выбрать самому» или «отдаться случаю» (колесо фортуны выбирает предмет; темы идут по заранее заданной хронологии).
- Предметы: Математика (ЕГЭ), Русский (ЕГЭ), Информатика (ЕГЭ), Физика (ЕГЭ), English (уровень 10 класса), Алгебра (10 кл.), Геометрия (10 кл.), Python.
- Исходная цель ТЗ — 100 уроков на предмет и 10 проверок на урок. **Фактически сейчас: 8 уроков на предмет (64 всего), по 12 вопросов в уроке** (прогресс идёт по кругу: индекс урока = `S.p[id] % 8`). Расширение до 100 уроков — открытая задача.

## 4. Веб-часть (`www/index.html`)

Стек: чистый JS без сборщика, один `<script>` + внешний `theory.js`. Данные хранятся в `localStorage` (ключ `bit`). Капсулируется Capacitor'ом в APK (WebView, схема `https://localhost`).

### 4.1 Состояние `S` (сохраняется через `save()`)
`{subs:{id:важность}, time:'17:00', n:уроковВДень, p:{id:прогресс}, total:всегоУроков, xp, streak, last, day:toDateString(), cnt:пройденоСегодня, setup:bool, askedNotif?}`.
Сброс дня: если `S.day !== today()` → `cnt=0`. `save()` дополнительно вызывает `pushState()` (синхронизация с нативной службой).

### 4.2 Данные уроков
- `D` — объект предметов: `ids = Object.keys(D)` = `math, rus, inf, phy, eng, alg, geo, py`. `D[id] = {n:название, e:эмодзи, L:[[заголовок, краткоеПравило, статичныеВопросы], …]}`. Массив `L` дорастает до 8 уроков в коде `MORE` (placeholders `[title,'',[]]`), реальные вопросы берутся из `G`.
- Вопрос: `[текст, [варианты], индексВерного, пояснение]`.
- Помощники: `MQ(q,a,[неверные],sol)` (перемешивает, делает варианты уникальными), `NQ(q,a,sol,deltas)`, `PQ('вопрос|в1;в2;в3|idx|пояснение')`, `TF('вопрос|1/0|пояснение')`, `PR(list,f)` (список статичных вопросов → `{l,f}`), `SH`/`SHP(prefix)` (PQ с перемешиванием вариантов), `fm` (десятичная с запятой), `ns(k)` (k разных чисел), `rnd`, `pick`, `shuf`.
- `G` — генераторы: `G['math0']`…`G['py7']` (функции, возвращающие вопрос) либо `PR(...)`. `genQs(id,k)` собирает до 12 уникальных вопросов (до 120 попыток генерации).
- Теория: `THEORY[id+k]` строится `T(правила, примеры, совет, частаяОшибка)`; подробные тексты берутся из `window.THEORY_FULL` (`www/theory.js`: ключ `math0…py7` → массив из 4 строк) и **перекрывают** короткие версии (старые остались как запасной вариант, если `theory.js` не загрузится). **Правки теории делать в `theory.js`.**

### 4.3 Ход урока
`begin(id)` → если `S.total%4===3 && p>0` — урок-**повторение** (пул вопросов из всех изученных уроков предмета, без подсказок), иначе обычный урок `l=L[p%L.length]`. `LS={id,review,qs,title,th,i,lives,ok}`. `step()` → `theory()` (экран теории, кнопка «Понятно») → `quiz()` по вопросам → `finish()` (cnt++, total++, p[id]++, xp, streak, сохранение).
`ans(k,b)`: верно → «✅ Верно» (+1 к `LS.ok` только если с первой попытки); неверно → вариант блокируется, `lives--`, показывается «Осталось попыток: N из 3» и кнопка «📖 Посмотреть тему и правила» (не в повторении); при `lives==0` — показывается решение (+кнопка темы). `showTheory()/hideTheory()` — полноэкранная панель `#thv` (z-index 90) с теорией урока, возврат к вопросу сохраняет состояние.

### 4.4 Настройка и выбор урока
`setup1()` (предметы + важность 1–10) → `setup2()` (время, число уроков в день) → `afterSetup()` (запрос разрешений в нативном режиме) → `startChoice()` («Выбрать самому» → `manual()` / «Отдаться случаю» → `randomPick()` с колесом `drawW()/spinW()`, вероятность ∝ важности).

### 4.5 Баннеры-напоминания: два режима
**Веб-режим (запасной)** — работает, только пока приложение открыто: `tick()` раз в секунду; в `due` (время урока или демо) ставит `trig`, через 5 минут (демо — 5 с) `showBan()`; `closeBan()` → следующий показ через 60 с (демо 8 с); `stage=min(stage+1,3)`; `leaveFlow()` при выходе из урока откладывает показ; баннер не показывается при `inLesson`. `#ban` (z-index 99) с классами `s1/s2/s3`.
**Нативный режим** — когда есть разрешение «поверх других приложений» **и** служба отвечает (`nat.overlay && nat.run`): веб-баннер выключен, баннеры рисует Android-служба, JS только шлёт состояние (`pushState`) и опрашивает `getPending()` (нажали «Учиться» → `startChoice()`).
**Доступ к плагину из JS (важно):** `NB()` берёт `Capacitor.Plugins.BitReminder`, а если его нет — работает напрямую через `Capacitor.nativePromise('BitReminder', метод, опции)` (в проекте нет сборщика и `@capacitor/core` JS не подключён, есть только `native-bridge.js`, который Android внедряет сам). `isNativeEnv()` — мы внутри Capacitor-приложения.
**Карточка «Напоминания в фоне» (`#perm`) стоит НАД кнопкой «Начать урок».** Три вида: (а) нативный модуль не отвечает/плагин не найден — жёлтая карточка с **причиной ошибки** и версией (`nat.why`); (б) всё работает (есть оверлей, уведомления, служба отвечает) — компактная зелёная строка «Напоминания в фоне работают» + «⚙️ Подробнее»; (в) есть проблема или нажато «Подробнее» — полная карточка с кнопками разрешений, моделью телефона, версией, подсказкой по производителю, «Автозапуск и питание», «Настройки приложения», «Журнал службы» и выключателем «🔔 Тревога-уведомления» (`S.alarm`, по умолчанию вкл).
**Автозапрос разрешений:** при запуске (раз за запуск, `launchAsked`) приложение само запрашивает уведомления и предлагает (confirm) открыть настройки «Поверх других приложений», если разрешения нет; отказ не навязывается повторно до следующего запуска. На главной внизу показывается версия «Бит vX.Y.Z» (`APP_VER`).
**Возврат в приложение во время тревоги:** `refreshNative(true)` на `focus`/`visibilitychange`; если служба сообщает `alarming` — сразу `startChoice()`.
Демо: `toggleDemo()` включает `DEMO.on` (игнорирует выполненную цель дня), выключается само после урока.
`inLesson=true` во время выбора урока и урока (баннер не мешает); `leaveFlow()`/`startChoice()` вызывают `pushState()` (поле `busy`).

## 5. Нативная часть Android (`native/android/`, пакет `com.bogdan0805.learningapp`)

| Файл | Роль |
|---|---|
| `MainActivity.java` | `BridgeActivity`; регистрирует плагин `registerPlugin(BitReminderPlugin.class)` до `super.onCreate` |
| `BitReminderPlugin.java` | Capacitor-плагин `BitReminder` (мост JS↔native) |
| `BitReminderService.java` | Foreground-служба (`foregroundServiceType=specialUse`): тик раз в секунду, уведомления, оверлей-баннер |
| `ReminderLogic.java` | **Чистая** логика расписания баннеров (без Android) — покрыта Java-тестом |
| `WakeReceiver.java` | Страховка: будильник (`setAndAllowWhileIdle`) перезапускает службу, если её убили |
| `BootReceiver.java` | Запуск службы после перезагрузки/обновления (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`) |
| `EventLog.java` | Журнал событий (до 60 строк в SharedPreferences) + `device()` |

**Тревога-уведомления:** когда баннер дошёл до 3-й (последней) стадии и пока урок дня не пройден (и пользователь не в уроке, и `alarm` включён), служба шлёт уведомление **каждые 700 мс** (`alarmLoop`, канал `bit_alarm`, IMPORTANCE_HIGH, вибрация, один и тот же ID=3 — обновляется, тексты чередуются, `setOnlyAlertOnce(false)`), параллельно баннеру. Останавливается при выполнении цели дня, `busy`, выключении в настройках или отключении демо; флаг `alarming` в prefs читает JS. Логика условия — `ReminderLogic.alarmActive()` (тестируется в Java).
**Контракт JS → native** (`Capacitor.Plugins.BitReminder`, доступен в обычном JS благодаря JSExport/PluginHeaders):
`sync({enabled,time,n,cnt,dayKey,busy,demo,alarm})`, `hasOverlay()` → `{overlay,notifications,battery,running,lastTick,now,lastErr,device,maker,alarming}` (каждое поле собирается в своём try/catch, сбой одного пункта попадает в `lastErr`, а не ломает весь ответ), `requestOverlay()`, `requestNotifications()`, `requestBattery()`, `openAppSettings()`, `openAutostart()` (экран автозапуска производителя: Xiaomi/Huawei/Oppo/Vivo/Samsung, иначе настройки приложения), `getPending()` → `{start,alarming}`, `getLog()` → `{log}`, `clearLog()`.
`dayKey` = `${год}-${месяц1..12}-${день}` (без нулей) — обязан совпадать с форматом в службе.

**SharedPreferences `bit_reminder`:** `enabled,time,n,cnt,cntDay,busy,busyAt,demo,alarm,alarming,pending,lastTick,lastErr,lastWake,notifiedDay,log`.

**`ReminderLogic.tick(now,minutesOfDay,today,canOverlay)`** возвращает `NONE/DUE_NOTIFY/SHOW_BANNER/HIDE_BANNER`. Правила: выполнена цель дня (и не демо) → сброс; `due` = демо или время ≥ срока; первый тик после due: `trig=now`, `nextShow=now+5 мин` (демо 5 с) + одно уведомление за день; баннер показывается, если не `busy` (busy протухает через 3 мин без обновления), нет другого баннера, есть разрешение и `now≥nextShow`; закрытие/«Учиться» → `nextShow=now+60 с` (демо 8 с); `stage=min(stage+1,3)`.

**Служба:** `START_STICKY`; каждые 30 тиков переставляет будильник на +90 с (пока жива — будильник не срабатывает); `onTaskRemoved` → будильник через 2 с; `onDestroy` при `enabled` → будильник через 3 с; `lastTick` пишется каждые 5 тиков; ошибки пишутся в `lastErr`; события — в `EventLog` (старт/перезапуск/остановка, паузы тиков >5 с, смена разрешения, показ/ошибка баннера, нажатия, будильник, boot).
**Оверлей:** `TYPE_APPLICATION_OVERLAY`, flags `NOT_FOCUSABLE|LAYOUT_IN_SCREEN|LAYOUT_NO_LIMITS`, полностью программный UI (без ресурсов), цвета стадий `0xF2F59E0B / 0xF5EA580C / 0xFAB91C1C`, на стадии 3 дрожание `ObjectAnimator`. «Учиться» → `pending=true`, `startActivity(launchIntent)` (MainActivity `singleTask`), затем скрыть баннер.
**Манифест** (патчится `patch_android.py`): `SYSTEM_ALERT_WINDOW, FOREGROUND_SERVICE, FOREGROUND_SERVICE_SPECIAL_USE, POST_NOTIFICATIONS, RECEIVE_BOOT_COMPLETED, REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`; `<service … foregroundServiceType="specialUse">` с `<property PROPERTY_SPECIAL_USE_FGS_SUBTYPE>`; `<receiver>` WakeReceiver (не exported) и BootReceiver (exported). Код не использует androidx (чтобы компилироваться отдельно); `minSdk` Capacitor 6 = 22, `targetSdk` 34 (всё новое защищено `Build.VERSION.SDK_INT`).
Capacitor: `@capacitor/core|cli|android ^6.2.0` (на момент написания 6.2.2).

## 6. Сборка и релизы

Workflow `.github/workflows/build-apk.yml` (триггеры: push в `main`, `workflow_dispatch`): checkout → Node 20 → JDK 17 → `npm install` → `npx cap add android` → **`python3 native/patch_android.py`** → `npx cap sync android` → `./gradlew assembleDebug` → копия в `Bit-learning-app-003.apk` → **проверка подписи** (отпечаток APK должен совпасть с `native/debug.keystore`, иначе сборка падает) → artifact → релиз.
`patch_android.py`: копирует `native/android/*.java` в `android/app/src/main/java/com/bogdan0805/learningapp/` (MainActivity перезаписывается), патчит `AndroidManifest.xml`, ставит `versionCode/versionName`, **прописывает `signingConfigs.debug` на `../../native/debug.keystore`** (способ с копированием в `~/.android` НЕ сработал), идемпотентен. **Версию (`versionCode`, `versionName`) повышать в этом скрипте при каждом релизе** (сейчас 6 / 0.3.0).
Релизы GitHub:
- **`003`** («Версия 003 — тревога-уведомления и диагностика», файл `Bit-learning-app-003.apk`) — обновляется **каждым** пушем в `main`, `make_latest: false`. Это актуальная сборка.
- **`002`** («Версия 002…», `Bit-learning-app-002.apk`) — **заморожена** на версии 0.2.3 (коммит `cf1469e`); workflow её больше не трогает.
- **`latest`** («Последняя сборка APK», `Bit-learning-app.apk`) — **заморожена** по просьбе владельца (версия с веб-баннерами, коммит `e57d9a2`, «не замещать текущий апк»). Workflow её больше не трогает. Не удалять и не перезаписывать без просьбы.
Подпись: постоянный ключ → новые сборки ставятся поверх друг друга. Старые сборки (`latest` и первые сборки до фикса подписи) подписаны случайными ключами → при первом переходе владельцу нужно один раз удалить старое приложение (прогресс в localStorage при этом теряется).

## 7. Как проверять изменения (чек-лист перед пушем)

## 8. Подводные камни (набитые шишки)

- Вывод инструментов экранирует кавычки в JSON: в файле они обычные. Python-замены в `index.html` делать с `assert s.count(old)==1`, писать файл только после всех замен.
- `pushState()` вызывается из `save()` очень рано (до объявления `let inLesson`/`DEMO`) → внутри обёрнут в `try/catch` (TDZ). `NB()` и `pushState` объявлены как `function` (hoisting).
- В `index.html` есть глобальный `const TF=` (помощник «Верно/Неверно»); загрузка теории использует блок `{const TF=window.THEORY_FULL;…}` — локальная область, конфликта нет.
- В тест-стенде jsdom `theory.js` подставляется инлайном (заменой `<script src="theory.js">`), а `canvas.getContext` заглушён (колесо).
- `Math.log2`, `**`, шаблонные строки используются свободно (WebView современный). Вывод `java`/`node` с кириллицей: `-Dstdout.encoding=UTF-8`.
- В `.gitignore` корневой слэш у `/android/` обязателен (см. раздел 3).
- `native-bridge.js` всегда считает платформу нативной (`isNativePlatform = () => true`); в тесте «обычный браузер» мост нельзя внедрять вообще (`web:true` в `bridge_harness.js`). Один и тот же сбой в `hasOverlay` раньше **молча** скрывал карточку и все запросы разрешений (так владелец «не видел» запроса) — теперь причина всегда показывается; не возвращай `.catch(()=>{})` без отображения ошибки.
- Android: фоновые службы на Xiaomi/Huawei/Samsung/Oppo/Vivo часто убиваются оболочкой — это главный подозреваемый в открытой проблеме.

## 11. Открытые проблемы

**П-1. Баннер не появляется при свёрнутом/закрытом приложении, приложение «не просит доступ»** (телефон владельца; модель и Android-версия НЕ известны). Владелец проверил версии 0.2.1–0.2.3: баннер только внутри приложения; приложение ни о чём не спросило, дать доступ было негде; уведомления «есть».
**Ключевой вывод:** в 0.2.3 при любом сбое нативной стороны (плагин не найден или `hasOverlay` отклонён) карточка и запросы разрешений **молча не появлялись** — это ровно симптом. Тест на настоящем мосте это подтвердил. В 0.3.0: причина сбоя и версия всегда видны в жёлтой карточке, доступ к плагину через `nativePromise`, `hasOverlay` устойчив к частичным сбоям, разрешения запрашиваются сами при запуске, блок перенесён наверх.
**Следующий шаг:** попросить владельца поставить 0.3.0 (релиз `003`) и прислать скриншот верха главного экрана: (а) жёлтая «Нативный модуль не отвечает» + текст ошибки → чинить плагин/регистрацию; (б) зелёная строка → нажать «Подробнее», «Демо», свернуть, затем «Журнал службы»; (в) полная карточка с ⚠️ → пройти пункты. По журналу: нет «служба запущена» → службу не стартуют/убивают; «ОШИБКА показа баннера» → проблема окна; «НЕТ разрешения» → нет оверлей-разрешения; «тики приостанавливались» → процесс усыпляют. Если «модуль не отвечает» — проверить, что `MainActivity.java` в собранном проекте регистрирует плагин (`registerPlugin`) и что установлена именно сборка 003.

**П-2 (выполнено в 0.3.0).** Просьба владельца: уведомления параллельно с финальной стадией баннера, каждые 0,7 с → реализовано как «тревога-уведомления» (раздел 5) с выключателем в карточке. На телефоне не проверено; Android может ограничивать частоту/громкость повторных уведомлений.
